# Objetivo de la sesión

Dar inicio formal al diseño técnico de ARGOS, dejando atrás la etapa de conceptualización general para comenzar la definición del modelo conceptual del núcleo del sistema.

---

# Temas tratados

## 1. Metodología de desarrollo

Se acuerda que ARGOS será desarrollado siguiendo una metodología de ingeniería de software basada en documentación previa al desarrollo.

Toda decisión importante será documentada antes de ser implementada.

Se crea el repositorio oficial del proyecto en GitHub.

---

## 2. Repositorio oficial

Se aprueba Git como repositorio maestro del proyecto.

El repositorio almacenará:

* Documentación técnica.
* Arquitectura.
* Bitácoras.
* Decisiones de arquitectura (ADR).
* Reglas de negocio.
* Diagramas.
* Código fuente (cuando inicie el desarrollo).

Se establece que el primer objetivo del repositorio será documentar la arquitectura antes de escribir código.

# Decisiones de Arquitectura

## ADR-0001

### Expediente

Se define oficialmente que:

> **El Expediente es la unidad mínima de gestión dentro de ARGOS.**

Representa una necesidad institucional que debe ser atendida, resuelta y posteriormente conservada como parte de la memoria institucional.

Todo expediente será administrado con absoluta trazabilidad, integridad y seguridad.

El expediente pertenece a la institución.

Los departamentos únicamente ejercen la custodia temporal durante las diferentes etapas del proceso.

---

## ADR-0002

### Trámite

Se define oficialmente que:

> **El Trámite es el verbo del Expediente.**

El trámite representa la acción institucional que el expediente desarrollará para alcanzar una resolución.

Se establece que los trámites serán completamente configurables.

No existirán trámites programados directamente en el código fuente.

---

## ADR-0003

### Modelo Conceptual

Se establece la primera estructura conceptual del núcleo de ARGOS:

Institución

↓

Expediente

↓

Trámite

↓

Proceso

↓

Resolución

Esta estructura servirá como base para el diseño del modelo de datos.

---

## ADR-0004

### Evidencia

Se aprueba conceptualmente que ARGOS administrará Evidencias y no únicamente documentos.

Los documentos serán considerados uno de los posibles soportes de una evidencia.

Se identifican como posibles evidencias:

* Documentos.
* Fotografías.
* Videos.
* Audios.
* Correos electrónicos.
* Inspecciones.
* Informes.
* Resoluciones.
* Firmas digitales.
* Sellos Digitales ARGOS.
* Eventos del sistema.
* Resultados OCR.
* Auditorías.

Se acuerda desarrollar formalmente este concepto en la siguiente sesión.

# Avances del Proyecto

Durante esta sesión el proyecto cambia oficialmente de enfoque.

ARGOS deja de concebirse como un Gestor Documental y pasa a definirse como una Plataforma para la Gestión de Expedientes, Evidencias y Memoria Institucional.
