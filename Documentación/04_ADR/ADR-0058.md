# ADR-0058: credenciales iniciales y cuentas SUPERUSER

**Estado:** Aprobado por el propietario, 10-09-2026  
**Ámbito:** autenticación, administración y conservación de expedientes

## Decisión

Cada cuenta recibe una clave inicial de alta y queda marcada para cambio
obligatorio en el primer acceso. La clave que el usuario establezca debe tener
al menos ocho caracteres, una mayúscula, una minúscula, un número y un carácter
especial. El cambio se realiza después de la autenticación multifactor y la
cuenta no debe conservar la clave inicial.

Las cuentas SUPERUSER son personales, pueden existir varias y tienen nivel de
acceso 0. Pertenecen al equipo creador/proveedor de ARGOS y no se registran como
personal de la institución cliente. Su primer titular se registra durante el
arranque seguro; no se codifica una identidad ni una clave fija en el sistema.
Cada SUPERUSER tiene su propio correo externo a la institución para MFA y recuperación.
Cada acción de SUPERUSER, incluida una consulta, requiere su MFA y una aprobación
fresca de una autoridad institucional con correo verificado. La aprobación se
vincula a la sesión, acción, tipo y referencia del objeto, expira en tres
minutos y solo puede usarse una vez.

## Invariantes

- No existe cuenta compartida ni contraseña maestra.
- Las cuentas y autoridades se registran individualmente y pueden revocarse.
- Los expedientes y la bitácora de auditoría no tienen operación de borrado ni
  sobrescritura; una corrección siempre agrega evidencia nueva.
- Los códigos y claves no se escriben en bitácoras.
- La entrega de correo institucional debe estar configurada; el valor
  predeterminado falla cerrado.

## Consecuencia

El primer acceso queda guiado y requiere una operación adicional de cambio de
clave, a cambio de eliminar contraseñas de alta reutilizadas. La autorización
de nivel 0 exige intervención institucional verificable en cada operación.

La API expone este control mediante `/api/superuser/authorizations/begin` y
`/api/superuser/authorizations/complete`; ambos requieren una sesión MFA y la
cuenta SUPERUSER registrada en la misma institución. Si el correo institucional
no está configurado, la emisión falla cerrada.
