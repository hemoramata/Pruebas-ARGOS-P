# ADR-0059: cifrado de expedientes en reposo

**Estado:** Principio aprobado; OpenBao autohospedado como referencia  
**Ámbito:** almacenamiento y custodia de expedientes

## Decisión

El contenido sensible de los expedientes y sus evidencias se almacenará
cifrado. Las claves no se guardarán en la base de datos, en el cliente Desktop,
ni junto al respaldo. ARGOS solicitará las claves a un servicio externo de
gestión de claves (KMS/HSM) con identidad de servicio, rotación y revocación.

El servidor solo descifrará durante una operación autorizada y registrará la
acción sin registrar claves ni contenido. Los metadatos mínimos necesarios para
localizar y aplicar retención podrán permanecer separados del contenido cifrado.

## Invariantes

- El cifrado no habilita borrado, sobrescritura ni destrucción de expedientes.
- La pérdida o revocación de una clave no autoriza eliminar datos; activa un
  procedimiento de recuperación institucional.
- Las copias de seguridad conservan el mismo nivel de cifrado.
- La migración de datos existentes será aditiva y verificará cada expediente
  antes de retirar una representación anterior.

## Implementación de referencia y costos

ARGOS no impondrá una suscripción externa obligatoria por institución. La
implementación de referencia será OpenBao autohospedado con Transit, ejecutado
en infraestructura controlada por la institución o por el proveedor de ARGOS.
La integración se realizará detrás de `IEnvelopeEncryptionProvider`, para poder
usar Cosmian KMS, un HSM o un KMS de nube cuando una institución lo requiera.
El costo de infraestructura, operación, respaldo y soporte se separará del
precio funcional de ARGOS y se hará explícito en cada implantación.

OpenBao no se embebe dentro del instalador ni del proceso del servidor ARGOS.
Se entregará como componente opcional de infraestructura, mediante un paquete
de despliegue versionado (por ejemplo, contenedor o servicio administrado por
la institución), con configuración, políticas, TLS, respaldos y procedimiento
de sellado separados. El instalador de ARGOS solo podrá comprobar su
disponibilidad y registrar el adaptador; nunca generará ni imprimirá claves
maestras.

Esta separación permite aplicar parches de seguridad de OpenBao sin esperar una
nueva versión funcional de ARGOS, limitar el impacto de una falla y permitir
que una institución use su propio HSM o Cosmian KMS. Ya se incluyen adaptadores
para OpenBao Transit y para la API JOSE de Cosmian; otros KMS/HSM se conectan a
la misma interfaz sin modificar el dominio.

## Decisión pendiente de integración

Antes de cifrar datos reales debe definirse el procedimiento de custodia,
recuperación y rotación de OpenBao y, si aplica, del HSM institucional. Hasta
entonces, el proveedor anterior actual se considera almacenamiento de desarrollo y no debe
usarse como bóveda de producción.

## Corrección del adaptador Transit (13-09-2026)

El adaptador OpenBao envía `plaintext` al endpoint de cifrado y `ciphertext` al
endpoint de descifrado. Ambos incluyen `context` para derivación y
`associated_data` para autenticación AEAD, codificados en Base64 según el contrato
de Transit. Las respuestas se validan antes de crear el sobre: se exige un
cifrado con formato `vault:vN:...` y el descifrado debe devolver Base64 válido.
Las pruebas cubren respuestas vacías, versiones inválidas, errores HTTP y campos
malformados. El formato de los sobres existentes no cambia.
