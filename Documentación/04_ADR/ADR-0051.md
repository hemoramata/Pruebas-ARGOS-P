# ADR-0051 - Cliente Desktop sin custodia permanente de información

**Estado:** Aprobado  
**Fecha:** 7 de septiembre de 2026  
**Versión objetivo:** ARGOS Desktop 3.0  
**Aprobación del propietario:** Confirmada el 7 de septiembre de 2026

## Contexto

Cada funcionario utilizará un pequeño software ARGOS instalado en su equipo. Este
cliente debe permitir iniciar la atención y capturar la información aportada por el
contribuyente, pero la computadora del usuario no debe convertirse en un archivo
paralelo ni custodiar permanentemente información institucional.

En el vocabulario del dominio, el funcionario inicia un Trámite mediante la creación
de un Expediente. La creación o modificación de la definición institucional de un tipo
de Trámite continúa sometida al constructor, versionamiento y jerarquía de aprobación.

## Decisión

ARGOS Desktop será un cliente ligero. Podrá capturar datos, digitalizar documentos,
preparar Evidencias, solicitar firmas e iniciar Expedientes, pero transmitirá la
información a ARGOS Server para su validación y almacenamiento definitivo.

ARGOS Server será la única fuente oficial y la única custodia permanente de los datos
entregados por contribuyentes y demás participantes.

## Reglas obligatorias

1. Desktop no mantendrá una base de datos permanente con Expedientes, Evidencias,
   documentos ni datos personales recibidos.
2. El almacenamiento temporal solo se permitirá cuando una función técnica lo exija,
   por ejemplo escaneo, conversión, firma o transmisión.
3. Todo temporal sensible deberá estar cifrado, asociado a una operación identificable,
   tener vencimiento breve y eliminarse después de la confirmación del servidor.
4. La memoria de trabajo y los temporales deberán limpiarse también al cancelar, cerrar
   sesión, vencer la operación o ejecutar la recuperación segura del cliente.
5. Una operación solo se mostrará como recibida cuando ARGOS Server devuelva la
   confirmación e identidad institucional correspondientes.
6. Si la transmisión falla, Desktop informará claramente que el ingreso no quedó
   formalizado; no generará un registro local que aparente ser oficial.
7. Las credenciales, llaves y tokens utilizarán almacenamiento seguro del sistema
   operativo y nunca se mezclarán con los datos capturados.
8. La caché local se limitará a recursos no sensibles o copias controladas cuya política
   institucional autorice expresamente.

## Continuidad y modo desconectado

La prohibición de custodia permanente implica que el alta de un Expediente requiere
confirmación del servidor. Un eventual modo desconectado deberá ser objeto de otra
decisión arquitectónica que establezca cifrado, expiración, recuperación y conciliación;
no se presume autorizado por esta decisión.

## Consecuencias

- La pérdida o sustitución de una estación no elimina la memoria institucional.
- Disminuye el riesgo de copias dispersas de información de contribuyentes.
- El servidor necesita carga de archivos confiable, confirmaciones idempotentes y
  recuperación de transmisiones interrumpidas.
- Desktop necesita un administrador de temporales seguro y verificable.
- Web y Mobile deberán respetar el mismo principio de custodia central.

## Estado de implementación

La API ya establece al servidor como frontera de reglas y persistencia. El alta de
Expedientes, la transmisión de Evidencias, el administrador seguro de temporales y la
carcasa Desktop continúan pendientes.
