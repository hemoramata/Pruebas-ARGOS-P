# ADR-0049 - Clientes coexistentes y Desktop oficial

**Estado:** Aprobado  
**Fecha:** 7 de septiembre de 2026  
**Versión objetivo:** ARGOS 3.0 y evolución posterior  
**Aprobación del propietario:** Confirmada el 7 de septiembre de 2026

## Contexto

La visión de ARGOS distingue el servidor, donde residen las reglas institucionales,
de los medios utilizados por las personas. El propietario confirma el orden de entrega:
primero una aplicación local, después acceso web y finalmente una aplicación móvil.
Los canales posteriores no deben eliminar los anteriores; los tres deberán convivir.

El Infrastructure Blueprint ya declara a ARGOS Desktop como aplicación oficial de los
funcionarios y prohíbe que el cliente tome decisiones de negocio.

## Decisión

ARGOS tendrá tres clientes compatibles sobre los mismos servicios institucionales:

1. **ARGOS Desktop:** primera entrega y cliente oficial inicial, con ventana propia,
   integración local, caché y capacidades de estación de trabajo.
2. **ARGOS Web:** canal posterior para uso mediante navegador autorizado.
3. **ARGOS Mobile:** aplicación posterior para teléfonos y tabletas.

Los tres clientes consumirán la misma API y nunca implementarán reglas de negocio
independientes. Una institución podrá habilitar uno, dos o los tres canales según sus
necesidades, perfiles y políticas.

## Reglas

1. Desktop debe presentarse como una aplicación ARGOS con ventana propia; el funcionario
   no dependerá de abrir manualmente un navegador.
2. Durante una instalación pequeña, ARGOS Server podrá ejecutarse en la misma máquina,
   pero seguirá siendo una frontera lógica distinta del Desktop.
3. La interfaz web desarrollada podrá reutilizarse dentro de la carcasa Desktop cuando
   convenga, siempre que esto sea un detalle interno y se respeten las funciones locales.
4. Ningún cliente podrá modificar permisos, flujos, políticas o reglas fuera de la API.
5. Autenticación, autorización, auditoría y versión institucional serán comunes para
   todos los canales.
6. La incorporación de Web o Mobile será aditiva y no obligará a abandonar Desktop.
7. La Consola Web de Administración definida en ADR-0052 podrá acompañar la primera
   etapa Desktop; no equivale al cliente web operativo de funcionarios.

## Consecuencias

- La API actual y el asistente visual no se descartan: constituyen una interfaz
  reutilizable para Desktop y para el canal Web posterior.
- Se requiere un proyecto `ARGOS.Desktop` y una estrategia de distribución y actualización.
- Mobile deberá diseñarse sobre contratos API estables, no sobre acceso directo a la base.
- Las pruebas de reglas permanecen concentradas en Domain/Application/API; cada cliente
  añade pruebas de navegación y presentación.

## Estado de implementación

El asistente visual y su API están implementados. La carcasa Desktop con ventana propia,
el empaquetado local y el arranque coordinado con ARGOS Server están pendientes. Los
clientes Web público y Mobile corresponden a fases posteriores.
